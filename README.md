# FEYA — доставка цветов

Премиальная платформа доставки цветов (старт: Алматы, Казахстан). Клиентское приложение на Flutter, бэкенд на
Spring Boot + PostgreSQL, веб-консоль для флористов/поддержки/администраторов. Языки: **русский (по умолчанию),
қазақша, English**; валюта — ₸ (KZT); часовой пояс бизнеса — `Asia/Almaty`.

> Репозиторий создан с нуля. Что реализовано и что нет — честно перечислено в разделе
> [«Статус и ограничения»](#статус-и-ограничения).

## Быстрый старт

### Вариант 1: Docker Compose (PostgreSQL + бэкенд)

```bash
cp .env.example .env        # задайте POSTGRES_PASSWORD и FEYA_JWT_SECRET (≥ 32 символов)
docker compose up --build   # API: http://localhost:8080 · консоль: http://localhost:8080/admin/
```

> Compose по умолчанию запускает профиль `dev` (демо-каталог, коды OTP в ответе API, тестовые платежи). Для
> production см. [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

### Вариант 2: локально

```bash
cd backend && SPRING_PROFILES_ACTIVE=dev ./gradlew bootRun      # нужен PostgreSQL, см. docs/DEVELOPMENT.md
cd mobile  && flutter pub get && flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8080
```

Android-эмулятор обращается к бэкенду на `http://10.0.2.2:8080` (значение по умолчанию). Пример сборки web:
`flutter build web --release --no-web-resources-cdn --dart-define=API_BASE_URL=http://localhost:8080`.

### Демо-аккаунты (только dev-сид)

Вход по телефону: приложение само подставляет код, который dev-бэкенд возвращает в `devCode`.

| Роль | Телефон |
|---|---|
| Клиент | `+77010000000` (или любой новый номер) |
| Администратор / Поддержка | `+77000000001` / `+77000000004` |
| Флорист (Достык / Самал) | `+77000000002` / `+77000000005` |
| Курьер | `+77000000003` |

## Основной сценарий

Открыть приложение → каталог (поиск, категории) → букет → размер → корзина (промокод, пересчёт на сервере) → вход
по OTP → адрес → **реальные** слоты доставки или ASAP → получатель/открытка → заказ → оплата → статус заказа и
отслеживание. Со стороны персонала: флорист принимает и собирает заказ (консоль `/admin/`), курьер (API) забирает и
доставляет, поддержка/админ управляют заказами, возвратами и справочниками.

## Статус и ограничения

**Реализовано и проверено (автотесты + прогон в браузере против настоящего бэкенда):**

- Каталог: категории, поиск, сортировка, пагинация, размеры с отдельными ценами и наличием, остатки по точкам,
  фильтр по зоне доставки, избранное, отзывы (только после доставки, «подтверждённая покупка»), рейтинг.
- Корзина на устройстве + авторитетный серверный расчёт (цены, склад, промокод, доставка, упаковка).
- Адреса, зоны доставки, слоты (дедлайны, ёмкость, наценки), ASAP по рабочим часам, подарочные опции, получатель ≠ заказчик.
- Заказ с идемпотентностью, резервированием остатков, таймаутом неоплаты, автоматом статусов и правами по ролям.
- Платёжная абстракция, подписанные webhook, идемпотентность, сверка суммы, возвраты (авто при отмене + ручной),
  **sandbox-провайдер, отделённый от production**.
- Трекинг: polling + SSE; «живая» позиция курьера только при согласии, на смене и со свежими данными.
- Роли CUSTOMER/ADMIN/FLORIST/COURIER/SUPPORT, JWT с ротацией refresh, rate limit, аудит.
- Веб-консоль персонала; уведомления в приложении; локализация ru/kk/en; тёмная тема в стиле референса.

**Не сделано / требует ваших данных (подробности — в docs/):**

- Реальный платёжный шлюз и SMS-провайдер (нет реквизитов): только интерфейсы + sandbox/logging-реализации.
- Push (FCM): токены устройств принимаются и хранятся, но клиентская интеграция Firebase и серверная отправка не подключены.
- Карта: адрес вводится вручную; встроенной карты/выбора точки нет (есть открытие позиции курьера во внешней
  карте по шаблону ссылки). Приложение курьера — только API (`/courier/**`), мобильного UI курьера нет.
- Сохранённые карты («способы оплаты») — экран-пояснение: хранение карт возможно только на стороне провайдера.
- Android/iOS-сборки в этой среде не собирались (нет Android SDK/Xcode); проверены анализ, тесты и `flutter build web`.
- Docker-образ описан, но не собирался здесь (в песочнице нет работающего Docker-демона); `docker compose config` валиден.
- Каталог — вымышленные данные разработки и **иллюстрации**, нарисованные скриптом; перед запуском нужны реальные фото.
  Юридические тексты в приложении — краткие заготовки; нужна проверка юристом.
- Консоль персонала — на русском (внутренний инструмент); клиентское приложение полностью локализовано.
